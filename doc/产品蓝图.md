| 能力 | only-mini-tool |

## 1. 技术栈（冻结）

```
Desktop:   Tauri 2（自定义无边框标题栏）· Windows 优先
Backend:   Rust + Tokio
HTTP/OCR:  reqwest (rustls) · image · arboard
Frontend:  Vue 3 + TypeScript + Vite
DB:        SQLite 3（WAL）
IPC types: ts-rs → src/api/generated/
Toolchain: mise（Node + Rust）推荐
i18n:      vue-i18n（v1 以 zh-CN 为主）
Store:     composables；工具切换 = registry + keep-alive
UI:        无 UI kit；styles/tokens.css
```

---

## 2. 分层（硬约束）

```
Vue UI / composables / tools/*
        ↓
api/*（invoke 封装）
        ↓
commands（薄：反序列化 + 调 Service）
        ↓
services + domain（校验、OCR 引擎调度、业务规则）
        ↓
repository（SQL）
        ↓
infrastructure（database / filesystem / http 客户端等）
```

规则：

1. Command **不写**业务、**不写** SQL、**不写**厂商 HTTP 细节。  
2. Repository **不做**业务校验。  
3. 前端 **不直连** SQLite。  
4. OCR 识别执行与密钥读取在 **Rust Service / Engine**；前端只展示与发意图。  
5. 错误统一：`Result<T, AppError>` → `{ code, message }`，前端映射 i18n。

## 3. Tool Host 与工具模块

### 3.1 壳隐喻

对齐 **Android 式 Tool Host**（Launcher 桌面 + 全屏工具 Activity）：

| 概念 | 说明 |
|------|------|
| ToolLauncher | 工具桌面；registry 卡片网格 |
| AppTitleBar | 无边框自定义标题栏（标题 / 系统设置 / 窗控；按 `mainView` 切换） |
| BackFab | 客户区左上浮层返回（非 Home） |
| ToolStage | 按会话挂载工具根组件（回桌面可保活；关闭则 dispose） |
| SettingsView | **系统**设置（外观/调试），不进 tools registry |
| ToolConfigView | 工具自有配置；Section 来自 registry |
| StatusFeedback | 顶部 Message（分 type）；busy 在工具内 |

### 3.2 工具扩展模型

**编译期一等公民模块**（contribution），不是运行时插件。

前端 `ToolDefinition`（v1 字段）：

| 字段 | 说明 |
|------|------|
| `id` | 稳定标识，如 `ocr` |
| `labelKey` | i18n 键 |
| `descriptionKey` | Launcher 卡片描述（可选） |
| `icon` | Launcher 图标标识 |
| `order` | 排序 |
| `stage` | Stage 根组件 |
| `persistOnDeactivate` | 默认 `true`：回桌面保活；`false` 时返回即 dispose |
| `settingsSection` | 可选；工具配置 UI |
| `session` | `{ dispose() }`；关闭时清业务状态 |

**目录所有权**：按 `tools/<id>/` 组织；允许壳与工具按需 import（无 FE isolation 门禁）。**v1 无跨工具 bus**；工具内自管状态，避免无意义耦合。

v1.1+ 再考虑抽象：`settingsSections` 动态贡献、`shortcuts`。v1 工具配置经 registry 字段挂载。

**禁止**：为未上线工具注册 `enabled: false` 占位。

### 3.3 第二工具接入 checklist

1. `src/tools/<id>/`：Stage + session + 配置（+ 局部组件）  
2. `src/tools/registry.ts` 注册（仅上线时）：`stage`、`session`、`settingsSection?`、`persistOnDeactivate`  
3. 后端按需：`commands/<id>.rs` + services + repository + `api/<id>.ts` + domain ts-rs  
4. settings 键：`<id>.*` 与 Section 归 `tools/<id>/`；系统 SettingsView **不**编排工具段；配置从 Launcher 菜单进入  
5. 更新产品设计工具清单、技术实现命令表、项目进度  

硬约束：不改 ToolSession 对外 API（`open` / `deactivate` / `dispose`）；不直连 DB；Stage 自管内部 IA；复用 `components/common` primitives。

### 3.4 OCR 子系统边界

```
commands/ocr → OcrService → OcrRegistry(OnceLock) → dyn OcrEngine (engines/*)
                      ↘ Settings（ocr.engine.<id>.*；bundle get/save）
```

- **定义** `OcrEngine` + `EngineSpec` + `EngineConfig` + 归一化 `OcrResult`；`ocr.active_engine` 选择实现（默认百度）。  
- 设置 UI 按 `get_ocr_settings` 描述符渲染，**不执行**识别、不传引擎参数。  
- 识别 IPC：**路径为主**（`recognize_image(path)`），避免默认整图 base64 灌 IPC。

## 5. IPC 与类型

- Command：`snake_case`；serde `rename_all = "camelCase"`。  
- Domain DTO + `#[ts(export)]` 为 TS 契约**唯一源**；`mise run gen-types`（或等价）生成 `src/api/generated/`。  
- **禁止**手改 generated 类型文件。  
- 薄 `api/*.ts` 只做 `invoke` 封装。

## 6. 数据与外观

### 6.1 SQLite

- 路径：`{app_data_dir}/only-mini-tool/data.db`（最终以技术实现为准）。  
- `PRAGMA journal_mode=WAL; foreign_keys=ON;`  
- 访问：`with_conn` / `with_tx`；SQL 仅在 repository / migrations。  
- **settings KV**：一张表；`id` 代理主键 + `key` UNIQUE + `value` + `created_at`/`updated_at`。所有权：`ui.*`/`app.*` → 系统；`<tool>.*` → 对应工具模块（非多表）。业务表均遵循「id + 审计字段」约定（见技术实现）。  
- **OCR 密码字段**：OS keyring（Windows Credential Manager）；启动/读取时迁移旧 SQLite 明文并清空库内值。非密码字段仍在 KV。  
- 其它非密钥设置：v1 **明文**存储于 SQLite；依赖 OS 用户目录 ACL。

### 6.2 Appearance

- 偏好：`ui.theme` = `system | light | dark`。  
- 宿主 resolve + 全窗 `set_theme`；前端写 `html[data-scheme="light|dark"]`，无 attribute 时 CSS 回退 `@media (prefers-color-scheme)`。  
- **禁止** Naive 式 `data-theme` 与 media 双轨涂色；以 `data-scheme` + host 为唯一运行时契约。

## 7. 前端约定

| 项 | 约定 |
|----|------|
| 状态 | composable；无 Pinia |
| 导航 | registry + 视图枚举；无 Vue Router（无深链需求前） |
| 工具保活 | ToolStage `keep-alive` by toolId |
| 设置 | 特殊视图，非 Tool |
| 确认/菜单 | 自研；禁用 `window.confirm` / 默认右键 |
| OCR 布局 | Canvas 主表面 + 可配停靠 Inspector（左/右/下，默认右）；同层 transform 选框 |
| 业务注释 | 中文 |

共享 primitives：`AppButton`、`AppEmpty`、`AppContextMenu`、`AppMessage` / `AppMessageHost`、`AppInput`、`AppConfirm` 等（已落地）；`AppSplit` 等为规划、未实现。
**不**强制所有工具使用侧挂 Inspector。

## 9. 反模式（禁止）

- Command 内写 SQL / 厂商 HTTP / 复杂业务分支  
- 手改 `api/generated/*`  
- 前端与 Rust 各维护一份分叉的 OCR 结果结构（以 domain + ts-rs 为准）  
- 用浏览器 confirm / 默认右键充当桌面交互  
- 复刻旧 QML 侧栏 + 上下 Split 作为「平台标准」  
- Pinia + Vue Router + Naive UI 作为默认栈（与本文冲突）  
- `data-theme` 与宿主 `set_theme` 双写  
- 运行时插件、未上线工具灰图标占位  
- 识别命令从 UI 传入百度密钥  
- 把 only-todo 的 Float/托盘几何无脑拷入本项目
