## 1. 产品概述

### 1.1 产品定位

**only-tool** 是一款面向**个人开发者**的轻量级 Windows 桌面工具箱应用。它在一个主窗口中通过左侧导航栏承载多个独立的小工具，让用户不必为每个小需求单独安装软件。

当前版本仅保留并重制原 Tool-Boxes 项目中的**核心工具 —— OCR 图片文字识别**，但底层技术栈全面升级为 Vue 3 + TypeScript + Tauri 2 + Rust。

### 1.2 一句话介绍

> 一款轻量、可扩展的 Windows 桌面工具箱，首期提供基于百度 handwriting 云端 OCR 的图片文字识别工具。

### 1.3 核心价值

| 价值点 | 说明 |
|---|---|
| 即开即用 | 打开图片即自动识别，绿色识别框高亮每个文字区域，双击即复制 |
| 多输入方式 | 文件选择、剪贴板粘贴、拖放三路图片输入，贴合开发者操作习惯 |
| 引擎可扩展 | OCR 引擎模块化抽象，未来可快速接入腾讯、本地 Tesseract 等多种引擎 |
| 轻量原生 | Tauri 2 + Rust 打包，安装包小、内存占用低、启动快 |
| 生态可生长 | 工具箱形态，为后续更多小工具预留统一扩展框架 |

### 1.4 与旧项目的关系

| 维度 | 旧 Tool-Boxes | 新 only-tool |
|---|---|---|
| 技术栈 | Python 3 + PySide6 + QML | Vue 3 + TypeScript + Tauri 2 + Rust |
| 打包 | PyInstaller + UPX | Tauri Bundler（NSIS / MSI） |
| OCR 引擎 | 百度 handwriting（固定） | **引擎抽象化**，可插拔多引擎 |
| 首期工具 | OCR / 文件复制 / 系统设置 / GitHub 原型 | 仅 OCR |
| 定位 | 个人开发者工具箱 | 延续，平台化演进 |

## 2. 目标用户

| 用户画像 | 场景描述 |
|---|---|
| 个人开发者 | 从截图、报错图、表格图中快速提取文字用于检索/粘贴 |
| 办公用户 | 把纸质单据、拍摄照片中的文字转成可复制文本 |
| 效率工具爱好者 | 喜欢把高频小功能集中在一个轻量工具箱中 |

**核心用户诉求**：
1. 打开/粘贴图片后**最快路径**拿到可复制的文字；
2. 能**直观看到**每个文字被识别到的位置（识别框）；
3. 配置简单，密钥填一次即可长期使用。

## 3. 功能需求总览

首期 only-tool 仅含两个页面：

```
only-tool 主窗口
├── 左侧导航栏（Sidebar）
│   └── OCR 文字识别（唯一入口，默认页）
└── 内容区
    └── OCR 识别页面
        ├── 图片画布（识别框叠加）
        └── 结果面板（全文 + 复制日志）
```

功能模块清单：

| 模块 | 功能点 | 优先级 |
|---|---|---|
| 图片输入 | 文件选择、剪贴板粘贴、拖放 | P0 |
| OCR 识别 | 引擎配置、异步识别、进度/错误反馈 | P0 |
| 识别框 | 框叠加、hover 高亮、双击复制该词 | P0 |
| 结果面板 | 全文展示、复制全部、复制日志 | P0 |
| 图片操作 | 缩放、平移、修正方向、复原、清除 | P1 |
| 引擎管理 | 引擎选择、密钥配置、引擎抽象扩展 | P1 |
| 系统配置 | 主题（浅色/深色） | P2 |

## 4. 详细功能需求

### 4.1 图片输入（P0）

用户可通过三种方式加载图片：

| 方式 | 交互 | 说明 |
|---|---|---|
| 文件选择 | 右键菜单 →「选择图片」→ 系统文件对话框 | 支持 png / jpg / jpeg / bmp / gif / webp |
| 剪贴板粘贴 | 右键菜单 →「粘贴图片」/ 快捷键 `Ctrl+V` | 读取剪贴板位图，转临时图片 |
| 拖放 | 将图片文件拖入画布区域 | 校验扩展名，加载即识别 |

**验收标准**：
- 三种方式加载同一张图片，结果一致；
- 加载成功后自动触发识别；
- 加载新图片时清空上一次的识别结果与复制日志。

### 4.2 OCR 识别（P0）

- **识别引擎**：首期内置**百度 handwriting（手写/文字识别）云端 OCR**，需用户配置百度智能云 `API Key` 与 `Secret Key`。
- **触发时机**：图片加载完成即自动识别（原 Tool-Boxes 行为）。
- **异步处理**：识别在 Rust 后端异步执行，UI 不阻塞；识别期间展示「识别中…」加载状态。
- **超时与错误**：识别超时（默认 10s）或失败时给出明确错误提示，图片保留可重试。

**验收标准**：
- 网络正常且密钥有效时，返回 `words_result`（每个词条含文字与位置矩形）；
- 无密钥 / 密钥错误 / 网络失败时，错误信息清晰可读；
- 识别期间可继续缩放、平移图片（不卡顿）。

### 4.3 识别框叠加（P0）

识别结果以绿色矩形框叠加在图片上，框位置对应每个被识别文字的像素位置：

| 状态 | 样式 | 交互 |
|---|---|---|
| 默认 | 绿色边框、半透明背景 | 悬停指针变手型 |
| 悬停（hover） | 边框变红 | 提示该词文字 |
| 双击 | — | 将该词文字复制到剪贴板 |

**验收标准**：
- 识别框位置、大小与图片上的文字严格对齐；
- 缩放/平移图片时识别框跟随同步变换，不错位；
- 双击识别框，该词文字写入剪贴板并追加到「复制日志」。

### 4.4 结果面板（P0）

画布下方为结果面板，横向分割为两栏：

```
┌───────────────────────┬───────────────────────┐
│ 📝 OCR 识别结果        │ 📋 复制结果            │
│ （只读全文）            │ （复制历史，最新在上）  │
│  右键 → 复制全部        │  右键 → 复制全部      │
└───────────────────────┴───────────────────────┘
```

| 栏 | 内容 | 操作 |
|---|---|---|
| OCR 识别结果 | 全部识别文字按行拼接（`words.join('\n')`） | 只读；右键菜单「复制全部」 |
| 复制结果 | 复制历史日志（单条/全部），最新在上 | 右键菜单「复制全部」 |

**验收标准**：
- 识别完成后全文即时呈现；
- 「复制全部」复制全文到剪贴板并写入复制日志；
- 两栏分割条可拖动调节宽度。

### 4.5 图片操作（P1）

| 操作 | 交互 | 说明 |
|---|---|---|
| 缩放 | `Ctrl + 滚轮` | 范围 0.1 ~ 5.0，识别完成后自动适配视图 |
| 平移 | 按住左键拖拽 / 滚轮 | 图片超出视口时平移查看 |
| 修正方向 | 右键菜单 →「修正方向」 | 图片顺时针旋转 90°，旋转后重新识别 |
| 复原图片 | 右键菜单 →「复原图片」 | 缩放恢复 1.0、平移归零、居中 |
| 清除图片 | 右键菜单 →「清除图片」 | 清空图片、识别结果、复制日志 |
| 隐藏/显示识别框 | 右键菜单开关 | 切换识别框叠加层显示 |

### 4.6 OCR 引擎管理（P1）

- 提供「识别引擎」下拉选择（首期仅百度，注册表预留扩展位）；
- 引擎切换后，配置表单按引擎的 `configSchema` 动态渲染（如百度需 API Key / Secret Key）；
- 密钥保存本地（Rust 后端持久化），前端输入框以密码掩码显示；
- **扩展约定**：新增引擎只需实现统一接口并在注册表中登记，前端核心代码零改动。

### 4.7 系统配置（P2）

- 主题切换：浅色 / 深色（跟随系统可选，V1.x 实现）；
- Material-3 风格语义色板，全局 CSS 变量驱动。

| 编号 | 角色 | 故事 |

| US-1 | 开发者 | 作为开发者，我希望把截图直接粘贴进工具箱，就能自动识别出所有文字，方便我搜索报错信息。 |

## 6. 非功能需求（NFR）

| 类别 | 需求 | 验收口径 |
|---|---|---|
| 性能 | 识别异步执行，UI 不阻塞 | 识别期间缩放/平移流畅 |
| 性能 | 安装包体积小、启动快 | Tauri 打包显著优于旧 PyInstaller 体积 |
| 安全 | 百度密钥本地保存，不写入前端代码 | 密钥仅 Rust 后端读取使用 |
| 安全 | 配置落盘为本地文件 | 存储路径位于系统用户配置目录 |
| 易用 | 零门槛出结果 | 打开图片 → 自动识别 → 高亮框 + 全文，三步以内 |
| 可扩展 | OCR 引擎可插拔 | 新增引擎不修改前端核心页面 |
| 可扩展 | 工具箱可承载多工具 | 左侧导航为注册式扩展点 |
| 兼容 | Windows 10/11 | 依赖系统 WebView2 Runtime |
| 可靠性 | 断网 / 密钥失效时优雅降级 | 错误提示明确，不崩溃，可重试 |

## 7. 界面与交互设计

### 7.1 主窗口布局

```
┌─────────┬──────────────────────────────────────┐
│  ☰ 导航  │                                      │
│ ┌─────┐ │                                      │
│ │📄OCR │ │          内容区（路由视图）           │
│ │文字识别│ │                                      │
│ └─────┘ │                                      │
│         │                                      │
└─────────┴──────────────────────────────────────┘
 左侧边栏   右侧路由内容（OCR 页面）
```

- 窗口标题：`only-tool`
- 默认尺寸：约 960 × 640，可自由缩放
- 左侧边栏：工具图标 + 名称，当前选中项高亮

### 7.2 OCR 页面布局

```
┌────────────────────────────────────────────────┐
│ 图片画布区（可滚动视口）                          │
│   ┌──────────────────────────────┐              │
│   │ 图片 + 绿色识别框叠加层       │              │
│   └──────────────────────────────┘              │
│   右键菜单：选择图片/粘贴/修正方向/隐藏框/复原/清除│
├─────────────────────────── 可拖动分割线 ─────────┤
│ 📝 OCR 识别结果  │  📋 复制结果                  │
│ （只读全文）      │  （复制日志）                 │
└────────────────────────────────────────────────┘
```

### 7.3 主题

- **浅色主题**：白色系底色、灰阶表面色、深色文字；
- **深色主题**：深灰底色、浅色文字（Material-3 语义 token）；
- 识别框颜色为语义固定色：绿 / 红，不随主题变化。

## 9. 成功指标（V1.0）

| 指标 | 目标 |
|---|---|
| OCR 单图识别耗时（中等图片） | ≤ 3s（含网络往返） |
| 识别结果展示正确率 | 与百度接口返回一致，无丢词 |
| 识别框对齐准确度 | 缩放/平移下无肉眼错位 |
| 首次配置到首次识别成功路径 | ≤ 2 分钟 |
| 安装包体积 | 显著小于旧 PyInstaller 包 |
