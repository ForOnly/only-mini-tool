# only-tool 产品蓝图（Roadmap）

> 项目代号：only-tool
> 版本：v1.0（草案）
> 技术栈：Vue 3 + TypeScript + Tauri 2 + Rust
> 关联文档：[01-产品设计文档.md](./01-产品设计文档.md) · [03-技术实现文档.md](./03-技术实现文档.md)

---

## 1. 产品愿景

> 将 only-tool 打造为一个**轻量、可扩展的个人开发者桌面工具箱平台**：一个主窗口承载多种高频小工具，OCR 是第一个落地工具，后续按需孵化文件处理、GitHub 辅助、系统小工具等；同时让 **OCR 识别引擎生态化**——云端引擎（百度/腾讯）与本地引擎（Tesseract/rust-ocr）可按需插拔。

**愿景四支柱：**

| 支柱 | 描述 |
|---|---|
| 工具平台 | 左侧导航 + 路由 + 统一配置/主题/组件库，新工具即插即用 |
| OCR 引擎抽象 | 一套统一接口，多引擎热切换，前端零侵入 |
| 轻量原生 | Tauri 2 + Rust，小体积、低占用、快启动 |
| 渐进演进 | 从 OCR 单工具起步，分阶段扩展不返工 |

### 2.1 V1.0 — OCR MVP（首期）

**目标：把原 Tool-Boxes 的 OCR 工具 1:1 重制到新技术栈，跑通完整闭环。**

功能范围：

| 模块 | 交付内容 |
|---|---|
| 应用骨架 | Vue 3 + TS + Vite 工程、Tauri 2 Rust 壳、左侧边栏 + 路由 |
| OCR 工具 | 图片三路输入（选择/粘贴/拖放）、百度 handwriting 识别、识别框叠加、结果面板 |
| 图片操作 | 缩放（0.1~5.0）、平移、修正方向、复原、清除、隐藏/显示识别框 |
| 剪贴板 | 复制单词 / 复制全部、复制日志 |
| 配置 | 百度密钥配置（Rust 侧持久化）、浅色/深色主题 |

**完成标准**：
- `npm run tauri dev` 可启动；`npm run tauri build` 产出 NSIS/MSI 安装包；
- OCR 工具行为与原 Tool-Boxes 对齐（验收口径见 PRD §4）；
- 百度密钥本地保存、前端不落地。

### 2.2 V1.x — 引擎生态 + OCR 增强

**目标：OCR 模块真正"可插拔"，并提升识别结果的交互体验。**

| 迭代 | 内容 |
|---|---|
| V1.1 | OCR 引擎抽象落地（`trait OcrEngine` + 注册表 + 前端 descriptor），百度引擎重构接入 |
| V1.2 | 第二引擎：**本地 Tesseract**（`tesseract` 命令行或 `leptess` crate）实现离线识别 |
| V1.3 | 第二云端引擎：**腾讯 OCR**（可选） |
| V1.4 | OCR 结果增强：识别框点击定位、置信度显示（引擎提供时）、结果复制格式选择 |
| V1.5 | 配置增强：引擎一键切换、跟随系统主题、密钥 keyring 加密存储（评估） |

**完成标准**：
- 切换引擎无需改前端核心页面，仅下拉选择 + 动态配置表单；
- 离线可用：无网络时本地 Tesseract 可完成识别。

### 2.3 V2.x — 工具箱平台化

**目标：从一个工具演进为多工具平台。**

| 迭代 | 内容 |
|---|---|
| V2.0 | 平台能力：统一组件库（按钮/输入/分割面板/菜单/弹窗）、系统设置页、全局事件总线 |
| V2.1 | **GitHub 工具**：仓库文件树浏览（复用旧项目 `GithubFileModel` 树模型设计）、release 下载 |
| V2.2 | **文件处理工具**：目录复制（重构旧 FileOwner 功能，补齐目录树重建与去重） |
| V2.3 | 自定义无边框窗口 + 菜单栏、窗口状态持久化 |
| V2.4 | 更新机制：Tauri Updater 自动更新、遥测/日志上报（可选） |

**完成标准**：
- 侧边栏 ≥ 3 个工具，新工具接入无需改动平台代码；
- 统一的设置页管理主题/引擎/快捷键。

### 2.4 V3.x — 生态化与跨平台

**目标：从个人工具走向生态产品。**

| 迭代 | 内容 |
|---|---|
| V3.0 | 插件机制：第三方工具以插件形式接入（协议化 manifest） |
| V3.1 | 本地 OCR 引擎深度集成：纯 Rust 端到端模型（rust-ocr / candle 推理） |
| V3.2 | 多语言 i18n（中文 / English） |
| V3.3 | 跨平台：macOS / Linux 支持（Tauri 天然支持，适配打包） |
| V3.4 | 快捷键体系、全局唤醒（托盘）、屏幕区域截图直送 OCR |

**完成标准**：
- Windows / macOS / Linux 三平台安装包；
- 至少一个第三方插件在官方插件市场形态下可安装。

## 4. 技术演进路线

```
V1.0                     V1.x                   V2.x                  V3.x
┌─────────────┐   ┌──────────────┐   ┌───────────────┐   ┌───────────────┐
│ Vue3+TS+Vite │──▶│ OcrEngine 抽象│──▶│ 统一组件库     │──▶│ 插件机制       │
│ Tauri2 壳     │   │ Tesseract 本地│   │ 多工具路由     │   │ rust-ocr 本地  │
│ 百度 OCR     │   │ 腾讯 OCR     │   │ 设置页/事件总线 │   │ 多语言/跨平台  │
└─────────────┘   └──────────────┘   └───────────────┘   └───────────────┘
   单体工具            引擎生态            工具平台            产品生态
```

**关键架构投资点（必须在前置阶段做对）**：

1. **OCR 引擎抽象（V1.0 就要按 V1.1 的口径设计）**：`trait OcrEngine` + 归一化 `OcrResult` + 注册表，避免后期重构；
2. **IPC 数据契约**：Rust ↔ 前端使用 camelCase 归一化结构，密钥永远留在 Rust；
3. **主题 token 化**：CSS 变量语义色板，新组件/新工具自动继承；
4. **注册式扩展**：侧边栏、引擎、未来插件均为注册表驱动，避免硬编码。

## 5. 工具孵化候选池（V2.x 及以后）

依据旧 Tool-Boxes 的生态定位与现有代码资产，候选工具池：

| 工具 | 来源 | 价值 | 建议版本 |
|---|---|---|---|
| GitHub 工具 | 旧项目有树模型原型（`GithubFileModel`） | 仓库文件浏览/下载 | V2.1 |
| 文件复制工具 | 旧项目 FileOwner（需重构补齐目录树） | 批量/去重复制 | V2.2 |
| 屏幕区域截图 OCR | OCR 能力延伸 | 即截即识 | V3.4 |
| JSON/时间戳格式化 | 开发者高频 | 快速小工具 | V2.x 随需 |
| 编码转换（Base64/URL） | 开发者高频 | 快速小工具 | V2.x 随需 |

> 原则：**每个新工具必须复用平台能力**（配置/主题/组件/IPC），仅贡献自身业务逻辑。

## 6. 风险与依赖

| 风险/依赖 | 等级 | 影响 | 应对 |
|---|---|---|---|
| 百度 API 调用限额 / 计费 | 高 | 识别成本与可用性 | 提供本地引擎兜底；文档明示限额；错误提示明确 |
| 网络依赖（云端识别） | 中 | 离线不可用 | V1.x 落地 Tesseract 本地引擎 |
| WebView2 Runtime 依赖 | 中 | 旧系统可能缺失 | 安装包勾选自动安装 WebView2 |
| 密钥安全 | 中 | 明文存储泄露风险 | 密码框掩码 + V1.5 评估 keyring 加密 |
| Rust 生态学习成本 | 中 | 开发效率 | 引擎抽象收敛在少数文件，规模可控 |
| 识别框对齐精度 | 低 | 体验细节 | 坐标同层同 scale 方案，技术文档已规避错位 |

## 7. 产品迭代节奏

```
V1.0  ──▶ 验证 OCR 核心价值与稳定性
 V1.1 ──▶ 引擎抽象闭环，为多引擎铺路
 V1.2 ──▶ 本地离线可用，消除网络单点依赖
 V2.0 ──▶ 平台化，第二个工具（GitHub）验证扩展性
 V3.x ──▶ 生态化，插件 + 跨平台
```

每个版本发布前执行：

1. PRD 功能验收（对照 §4 验收标准）；
2. `tauri build` 安装包冒烟测试（全新机器安装运行）；
3. 版本号与更新日志同步。
