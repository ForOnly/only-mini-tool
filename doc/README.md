# only-mini-tool 文档中心

本目录是产品与工程的**唯一权威文档源**。实现与需求冲突时，以本目录权威文档为准。

## 权威文档

| 文档 | 职责 | 何时更新 |
|------|------|----------|
| [产品设计文档.md](./产品设计文档.md) | WHAT — 定位、平台/OCR 体验、Must/Should/Won’t、验收 | 需求、交互、验收变更 |
| [产品蓝图.md](./产品蓝图.md) | 架构硬约束 — 分层、Workbench、扩展契约、反模式 | 架构、目录、IPC、扩展模型变更 |
| [技术实现文档.md](./技术实现文档.md) | HOW — 模块、表、命令、OCR 引擎、前端组件、token | 接口、表结构、实现方案变更 |
| [项目进度.md](./项目进度.md) | LOG — 里程碑与变更记录 | 每次实质改动追加 |

与 only-* 家族映射：产品设计 ≈ 产品需求；产品蓝图 ≈ 架构蓝图；技术实现 ≈ 技术设计。

## 阅读顺序

1. 产品设计文档 → 边界与体验  
2. 产品蓝图 → 分层与扩展契约  
3. 技术实现文档 → 模块与接口  
4. 项目进度（有则）→ 当前阶段

## 同步纪律

1. 同一任务内：改需求 → 产品设计；改架构/表/协议 → 蓝图与/或技术实现；实质改动 → 进度日志。  
2. 禁止只改代码不改权威文档。  
3. 改 Rust DTO 后执行类型生成；禁止手改 `src/api/generated/**`。  

## 产品一句话

**only-mini-tool**：Tauri 2 + Vue 3 + Rust 桌面工具箱；v1 = Workbench 壳 + 多引擎 OCR（默认百度；UI 不复刻旧 QML）。
